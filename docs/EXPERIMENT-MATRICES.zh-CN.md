# 批量实验、算法导入与项目清理

本说明对应 0.4.0 的工作流。管理端和算力端都更新后，指定 GPU 和远程项目清理才能完整生效。

## 导入算法

在「算法项目」选择原始算法根目录，再选择实际 Python/bash 入口。导入只读取文件，生成外置配置；发布时创建独立快照。

常规配置在表单内完成：入口命令的各个参数、固定值与实验参数、参数类型及命令行绑定、数据文件选择、依赖和资源预算。需要比较的数据集名称、seed、学习率等应保留为实验参数。输出目录、分配的 GPU 等可以用固定参数映射到实验台提供的路径或设备。

日志指标可以使用示例模板提取，例如 `epoch={step} loss={loss}`。粘贴真实的示例日志，测试是否能提取正确的步数和数值；后端使用与运行时一致的 Python 正则表达式测试。复杂日志也可以直接编辑规则。原程序没有输出的指标不能凭空生成。

高级 JSON 编辑仍保留；应用成功或失败的提示显示在按钮旁。修改配置后要重新核对并保存，发布前检查文件预览。

### 可选 AI 辅助

「设置与帮助」支持 DeepSeek 和兼容 Chat Completions 的服务，可填写基础地址、模型和 API Key，并测试连接。默认地址是 `https://api.deepseek.com`，模型可自行修改。接口格式参考 [DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。本机兼容服务可使用回环 HTTP 地址。

AI 默认关闭。点击获取建议会发送当前导入配置、静态识别信息、补充要求及填写的示例日志；只有勾选包含源码时才附加所选入口的前 32,000 字节，不读取或发送数据集文件。API Key 保存在管理端数据目录的 `ai-settings.json` 中，界面仅显示是否已配置，不回显密钥。该文件包含凭证，备份时应按管理端凭证保存。

建议先经过配置校验，再显示修改前后的差异。应用建议只更新当前草稿，仍需要正常保存和发布。AI 不自动执行命令、修改原始源码、启动实验或替用户确认原生续训支持。连接失败、超时或建议无效时，已有配置保留。

## 从单次实验到矩阵

先把算法项目分发到希望使用的算力机，等待安装完成。然后在「实验矩阵」创建配置，选择已部署项目的实验预设。

例如 SASRec Original 要比较五个数据集：

1. 添加五个数据集条目，各自设置算法使用的数据集参数，例如 `data_name`。名称要与实际数据文件一致。
2. 如需比较多个 seed 或学习率，再添加参数组合。例如五个数据集 × 两个 seed × 两个学习率会生成 20 个实验；单矩阵一次最多 256 个组合。
3. 设置算力分配方式和优先级，预览数量与预计分配结果。
4. 保存矩阵并一键启动。每个组合是独立实验，管理端会持续分配可运行的任务；暂时没有合适资源的实验留在队列中。

矩阵可以新建、查看、修改、复制和删除。每次启动单独记录配置版本和批次；后续编辑矩阵不会改写已经提交的实验。重复传输同一次启动请求不会重复创建实验。运行中的矩阵需要先结束实验并等待节点确认，才能删除；删除保留历史实验记录。

### 算力分配方式

| 方式 | 用法 |
| --- | --- |
| 自动 | 在已安装兼容项目、在线且允许接单的机器间，按资源兼容性、队列负载及节点速度配置分配。 |
| 半自动 | 限定候选机器，或设置偏好顺序；候选范围是硬限制，偏好机器不可用时才考虑后续候选。 |
| 手动 | 指定一台机器，可进一步限定 GPU；不可用时等待，不会悄悄换机器或显卡。 |

优先级范围是 -100 到 100，数值越大越早分配尚未归属节点的任务，不抢占已经运行或已经分配的实验。CPU、内存、显存、独占/共享、运行时段和节点并发限制继续生效。GPU 限定要求算力端报告 `scheduler-v2` 能力。

同一项目在不同机器上的源码路径、Git 提交和运行环境可以不同，调度器使用目标机器同一项目版本/预设的部署记录。实验参数不会随分配被替换。失联实验继续保留原节点归属，避免重复训练。

## 整理结果

矩阵中的 Markdown 导出包括状态统计、数据集、算法、指标协议、批次/配置版本、节点、运行时长、最新指标、参数和状态详情，可直接保存为实验记录。

缺失结果显示为 `—`；失败或运行中实验保留其真实状态。报告不把不同指标协议混在一起排名或求平均，也不把部分结果当成最终结果。实验文件的回传可能晚于训练结束，完整模型与日志仍从实验详情下载。此导出使用确定的规则，不需要配置 AI。

## 删除算法项目

在项目卡片删除项目后，项目会从库中移除，并显示各机器的清理进度。管理端删除已发布的包；每台已部署机器收到请求后清理受管理的源码/数据副本、下载缓存、Git 缓存和工作副本、该项目已停止的 Docker 容器及确认无其他引用的派生镜像。

导入前的原始算法目录和数据文件、已归档的实验历史/结果不删除。其他项目使用的数据和运行环境会保留，基础镜像和共享镜像仓库不会全局清空。Docker 共享层、构建缓存及镜像仓库的空间可能仍被其他资源持有；清理不执行全局 prune。

有活动实验或未确认的停止/恢复命令时，删除会被拒绝。暂停或失败的实验可以随项目一起解除部署，但项目删除后不能再从原检查点恢复该部署；历史记录与输出仍可查看。

离线机器的清理请求持久保留，重新上线后处理。旧版算力端需要更新以支持 `project-delete-v1`。如果 Docker 不可用、配置发生变化或无法确认文件属于实验台，会显示失败原因；修复后可重试，不会把未执行的清理显示为成功。

## 本次验证范围

发布前执行完整 Python 回归，以及 Python 3.10 的矩阵、调度、AI、迁移与打包兼容检查；JavaScript 回归覆盖计时、矩阵提交重试与并发防抖、导入编辑和错误反馈。原生 Windows 验证覆盖两个角色的编译、升级版本/资产选择、安装交接、图标及高 DPI 行为。

浏览器验证使用独立管理端与模拟算力节点，覆盖两数据集 × 两个 seed 的预览、保存后编辑、分配及启动，Markdown 接口与内容、手动分配约束、实际日志正则测试、本地模拟 AI 服务设置/建议预览/应用、草稿保存、JSON 成功/失败提示及侧栏收起后的高 DPI 图表。Docker 删除使用模拟命令和真实隔离文件验证，未删除真实机器的容器；AI 服务协议使用本地模拟服务验证，未消耗真实提供商额度。
