# Experiment Manager 0.4.4

## 算力端显卡设置

- Experiment Worker 新增“显卡设置”，按名称、UUID 和本地状态列出显卡。
- 对本地未启用且已有匹配运行环境的卡，可直接点击“检查并启用所选显卡”。使用现有镜像验证 CUDA 设备 UUID 与运算，全部通过后备份原配置并启用，无需手动编辑 JSON 或运行终端命令。
- 等本机实验及回传完成后可检查；运行中的空闲代理自动停止并恢复。检查失败保留原配置并显示原因。原本停止的代理保持停止。
- 保留其他卡、项目、配对身份和整机资源预算。更新软件本身不会自动启用用户之前禁用的卡。
- 实验台的禁用显卡提示给出具体的算力端设置入口。已启用显卡的并发与显存预留继续在实验台配置。

验证覆盖配置保留、UUID 不匹配、CUDA 失败、检查超时、并发锁、代理恢复和桌面操作。硬件检查在用户点击启用时由目标机器执行；模拟测试不能替代实际 GPU 验证。

## 环境准备与后台服务

- 环境准备支持显式选择 `--setup-network host`，供已配置好专用 Docker 实例的 Linux 节点使用；镜像仓库只监听本机回环地址，训练与验卡仍使用无网络容器。默认安装继续使用 bridge。
- 保存并复用准备阶段选定的 Docker socket 和网络方式；项目分发不能改写节点的网络策略。
- 关闭 Registry 的默认调试监听，检查已有仓库的网络配置和重启状态，避免端口冲突或误用其他容器。
- 修复 systemd 用户服务中工作目录和日志路径的转义，保留原节点配置及实验数据。
