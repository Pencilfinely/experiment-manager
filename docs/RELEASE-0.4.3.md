# Experiment Manager 0.4.3

## 共享显卡与资源设置

公用双 A6000、单卡工作站和 Windows/WSL 算力端使用同一套共享规则：其他程序正在使用显卡不会直接阻止启动，实际剩余显存、预留和任务预算决定是否可以接着运行。新导入项目默认允许共享；仍可为单次实验或矩阵选择实验台内独占。

- 算力页面增加节点资源设置，可调整总并发、预取、CPU/内存预算，以及每张已启用显卡的并发与显存预留，无需修改节点 JSON。
- 资源设置持久保存，离线节点重连后应用，页面显示等待同步或已生效。并发编辑检查版本冲突；旧版算力端提示先升级。
- 单次实验和矩阵增加本次 CPU、内存、显存预算与共享选项。原项目、其他实验和历史批次保持独立。
- 新安装每张已启用显卡默认并发上限为 4，全节点为启用卡数 × 4。默认 CPU/内存预算仍保守，可通过表单调整。软件升级保留已有节点的 GPU 选择和资源配置。
- 设置影响后续启动，降低并发或预算不会终止正在运行的实验；本地未启用的卡不会通过远程资源设置被自动启用。

当前仍保守为已有实验预留其声明预算。GPU 显存没有硬隔离，共享不保证运行速度不受影响；外部程序同时分配显存仍可能造成显存不足。独占只约束实验台内任务，不锁住外部程序，也没有自动迁移或抢占它们的行为。

同时包含未发布导入草稿的空值修复：草稿的项目字段为 `null` 时，项目删除、删除恢复和导入列表可正常处理，不再触发 Internal service error。

## 使用与升级

更新管理端及需要远程调整资源的算力端。已有节点升级后，在「算力 → 资源设置」调高原来的并发上限；已有独占项目在创建实验或编辑矩阵时切换为共享即可。历史实验不会被改写。

Ubuntu 首次部署双卡，无需指定 `--gpu`：完整解压 Ubuntu 算力 ZIP，用普通用户运行 `bash Install-Worker.sh --pairing /path/to/a6000.pairing.json`。完成环境准备后，检查状态、GPU 验收任务和结果回传，再分发真实算法。

Windows 可通过「检查更新」安装。管理端继续使用原数据目录；算力端继续使用原 Ubuntu、节点身份与配置。安装前完成当前实验及待回传文件。延续 0.4.2 的修复，管理端不会仅因没有未完成工作的节点离线而阻止更新。

## 验证

完整 Python 回归 369 项通过（6 项按平台跳过），JavaScript 计时、矩阵与资源表单共 24 项通过。资源策略新增测试也在 WSL Ubuntu 运行通过。共享准入覆盖外部占用、同卡并发、独占、显存/RAM预留及节点预算；资源同步覆盖丢失响应、重启、权限和更新停止期间的写入限制。

隔离管理端页面实测覆盖双卡并发设置、轮询时输入保留、设置确认，以及矩阵资源覆盖、分配预览、保存后重新打开。测试使用模拟 GPU 状态，没有启动真实训练或修改真实算力端的资源设置。
